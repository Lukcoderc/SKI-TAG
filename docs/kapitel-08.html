        Die Gateways

        Kapitel 8 · Stand 31. Oktober 2026

        Zwischen Chip und Server steht das Gateway: ein kleines Funkboard, das Notrufe hört und über WLAN weiterreicht. Dieses Kapitel zeigt, welche Hardware das im Test ist, wie die Software darauf aufgebaut ist, und wie die zwei Geräte aufgestellt werden.

        Wie viele Gateways ein ganzes Skigebiet braucht und wo genau sie stehen sollen, klären erst Kapitel 9 bis 11. Hier geht es nur um das einzelne Gerät.

        Die Hardware im Test

        Für den Test braucht ein Gateway nur drei Teile, zusammen knapp 56€:

        TeilMengeWofür
        Heltec WiFi LoRa 32 V3, 868 MHz (ESP32-S3 + SX1262, kleiner Bildschirm)2hört die Chips, reicht die Pakete über WLAN an den Server weiter
        Stabantenne 868 MHz, 3 dBi (SMA), mit Adapterkabel IPEX auf SMA2mehr Reichweite als die beigelegte Antenne
        USB-C-Netzteil 5V, 2A, mit 2m-Kabel2Strom an der Station

        Fest. Es ist ausdrücklich die Version V3, nicht V4: Die Gateway-Software ist für den V3-Chipsatz gebaut.

        Wie die Software aufgebaut ist

        Die Gateway-Software liegt im Ordner firmware/skitag_empfaenger, kompiliert mit ESP32-Core 3.0.7 für das Board „Heltec WiFi LoRa 32(V3)“, mit den Bibliotheken RadioLib, ArduinoJson und U8g2. Eingestellt wird sie über config.h: ein Name (E1, E2), bis zu drei WLANs (etwa ein Hütten-WLAN und ein Handy-Hotspot als Rückfall), die Server-Adresse, ein eigenes Gateway-Passwort und die Funkeinstellungen, die exakt zu denen des Chips passen müssen.

        Teil der SoftwareAufgabe
        Funk, auf Kern 1nimmt nur echte SkiTag-Pakete an (0xA7, 27 Byte), reicht sie über eine Warteschlange weiter, muss nie auf das Netz warten
        Netz, auf Kern 0schickt jedes Paket mit RSSI, SNR und Alter als POST /gw/up mit Bearer-Passwort an den Server; die Antwort enthält die Downlinks, die dann gesendet werden
        Pufferfällt das WLAN kurz aus, sammelt das Gateway bis zu 60 Pakete, statt sie zu verwerfen
        Lebenszeichenkommen keine neuen Pakete, meldet sich das Gateway trotzdem alle 10 Sekunden am Server
        Bildschirmzeigt WLAN-Status, Server ok oder Fehler, Paketzähler und den zuletzt gehörten Chip mit Signalstärke

        Die Verbindung zum Server läuft über TLS mit den ISRG-Stammzertifikaten von Let's Encrypt. Bleibt das Gateway 60 Sekunden ohne Reaktion stehen, startet ein Watchdog es neu.

        Entschieden, aber am PC geschrieben. Laut Übergabe ist diese Software fertig, lief aber noch nie auf echter Hardware. Erst der Test mit den gelieferten Heltec-Boards zeigt, ob sie auf dem Board so läuft wie geplant.

        Aufstellung im Test

        Für den Test kommt ein Gateway jeweils innen an ein Fenster einer Bergstation, möglichst hoch, mit senkrechter Antenne und Blick auf die Pisten. Strom und WLAN liefert die Station selbst, vorher muss geklärt sein, ob das dort genutzt werden darf.

        Geschätzt. Diese Aufstellung ist ein erster Plan, nicht gemessen: Wärmeschutzglas kann Funk stark dämpfen, eine Antenne außerhalb des Fensters wäre besser. Ob das an den Bergstationen so möglich ist, klärt Kapitel 11.

        Wenn mehrere Gateways gleichzeitig hören

        Hören beide Gateways denselben Chip, verwirft der Server das doppelte Paket über den Zähler, siehe Kapitel 4. Für Befehle an den Chip merkt sich der Server, welches Gateway ihn in den letzten 15 Minuten am besten empfangen hat, und schickt den Downlink über genau dieses.

        Das Ergebnis

        Fest: Zwei Heltec WiFi LoRa 32 V3 mit Außenantenne sind die Gateway-Hardware für den Test.

        Entschieden: Die Software trennt Funk und Netz auf zwei Kernen, damit der Funk nie auf das Netz warten muss, und puffert bis zu 60 Pakete bei einem WLAN-Ausfall. Fertig geschrieben ist sie, geprüft nur am PC.

        Offen: Ob sie auf echter Hardware wie geplant läuft, was bei einem Gateway-Ausfall geschehen soll, und wie sich das Gateway beim eigenen Server statt in der Cloud sicher anmeldet.
